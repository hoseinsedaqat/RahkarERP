# راهنمای فعال‌سازیِ «ورود با گوگل»

این راهنما قدم‌به‌قدم است و هیچ نیازی به دانشِ برنامه‌نویسی ندارد.
در پایان، کاربرانِ شما می‌توانند با دکمه‌ی «ورود با گوگل» واردِ برنامه شوند.

> **نکته‌ی امنیتی مهم:** من (دستیار) هیچ کلید یا توکنی از شما نمی‌گیرم و هیچ کلیدی
> در کد قرار نمی‌دهم. همه‌ی کلیدها را **خودتان** در فایل `.env` می‌نویسید.

---

## بخش اول — ساخت کلید در گوگل (حدود ۵ دقیقه)

1. وارد شوید: [Google Cloud Console](https://console.cloud.google.com/)
2. بالای صفحه روی انتخاب‌گرِ پروژه بزنید → **New Project**
   - نام: مثلاً `Rahkar ERP` → **Create**
3. از منوی کناری: **APIs & Services → OAuth consent screen**
   - نوع: **External** → Create
   - نامِ برنامه: `راهکار`
   - ایمیلِ پشتیبانی: ایمیلِ خودتان
   - دامنه، نشانی و سیاستِ حریم‌خصوصی را می‌توانید خالی بگذارید (برای استفاده‌ی داخلی)
   - در بخش **Test users** ایمیلِ کاربرانی را که قرار است وارد شوند اضافه کنید
     (تا زمانی که برنامه را منتشر نکرده‌اید، فقط این افراد می‌توانند وارد شوند)
   - Save and Continue تا پایان
4. از منو: **APIs & Services → Credentials → Create Credentials → OAuth client ID**
   - Application type: **Web application**
   - نام: `Rahkar Web`
   - **Authorized JavaScript origins** — نشانیِ سایت‌تان را وارد کنید، مثلاً:
     ```
     http://localhost:4000
     https://h03einsedaqat.github.io
     https://your-domain.com
     ```
   - **Authorized redirect URIs** — همان نشانی‌ها (در این برنامه ریدایرکت استفاده
     نمی‌شود، اما گوگل پر کردنش را می‌خواهد)
   - **Create**
5. پنجره‌ای باز می‌شود که **Client ID** را نشان می‌دهد؛ رشته‌ای شبیه
   `1234567890-abc...apps.googleusercontent.com`.
   آن را کپی کنید.

---

## بخش دوم — وارد کردنِ کلید در برنامه

فایل `.env.example` را کپی کرده و نامش را `.env` گذاشته‌اید (اگر نه، حالا این کار را بکنید).
سپس این خطوط را پر کنید:

```env
GOOGLE_CLIENT_ID=1234567890-abc...apps.googleusercontent.com

# آیا کسی که اولین‌بار با گوگل وارد می‌شود، حسابش ساخته شود؟
#   false = امن‌تر؛ فقط کسانی که از قبل در سیستم تعریف شده‌اند وارد می‌شوند
#   true  = حسابِ جدید با کم‌دسترسی‌ترین نقش ساخته می‌شود
GOOGLE_AUTO_SIGNUP=false

# نقشِ حساب‌های جدید (در صورت true بودنِ بالا):
#   viewer | sales | warehouse | accountant | admin
GOOGLE_DEFAULT_ROLE=viewer

# محدود کردن به دامنه‌ی شرکتِ شما — بسیار توصیه می‌شود
GOOGLE_ALLOWED_DOMAINS=sherkat.com
```

سرور را دوباره اجرا کنید:

```bash
npm start
```

حالا در صفحه‌ی ورود، زیرِ فرم، دکمه‌ی **«ورود با گوگل»** ظاهر می‌شود.
اگر ظاهر نشد، بخشِ «عیب‌یابی» در پایین را ببینید.

---

## بخش سوم — افزودنِ کاربر (اگر `GOOGLE_AUTO_SIGNUP=false` است)

چون ساختِ خودکار غیرفعال است، باید ایمیلِ فرد را در سیستم تعریف کنید:

1. با مدیر سیستم (`admin`) وارد شوید.
2. بخشِ **هویت و دسترسی → کاربران و گروه‌ها → کاربر جدید**
3. نام کاربری را **دقیقاً برابر با ایمیلِ گوگلِ فرد** بنویسید (مثلاً `ali@sherkat.com`)
4. نقش و نامِ نمایشی را انتخاب کنید و ذخیره کنید.

از این لحظه آن فرد با همان ایمیل و دکمه‌ی گوگل وارد می‌شود؛ نیازی به رمز عبور ندارد
(رمزِ عبورش تصادفی و غیرقابلِ استفاده است و فقط ورود با گوگل کار می‌کند).

## بخش چهارم — استفاده از Supabase به‌جای تنظیمِ مستقیمِ گوگل (اختیاری)

اگر از Supabase استفاده می‌کنید، می‌توانید احراز هویت را هم به آن بسپارید.

1. در پنلِ Supabase: **Authentication → Providers → Google**
2. کلیدهایی را که در بخشِ اول از گوگل گرفتید اینجا وارد کنید و فعال کنید.
3. در Supabase: **Project Settings → API** دو مقدار را بردارید:
   - **Project URL** (مثل `https://abcdefgh.supabase.co`)
   - **anon public** key
4. در `.env` بنویسید:
```env
SUPABASE_URL=https://abcdefgh.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOi...
GOOGLE_ALLOWED_DOMAINS=sherkat.com
```

در این حالت، توکنی که مرورگر از Supabase می‌گیرد به سرورِ راهکار فرستاده می‌شود و
سرور با درخواست به `/auth/v1/user` صحتِ آن را بررسی می‌کند.

## بخش پنجم — برای نسخه‌ی اینترنتی (GitHub Pages)

نسخه‌ی Pages سرور ندارد؛ بنابراین لازم است سرورِ Node را جدا مستقر کنید (Render،
Railway، سرور شخصی، …) و نشانی‌اش را به frontend بدهید:

```bash
VITE_API_BASE=https://api.your-domain.com npm run build:demo
```

سپس در `.env`ِ سرور:
```env
CORS_ORIGIN=https://h03einsedaqat.github.io
GOOGLE_CLIENT_ID=...
```

و در تنظیماتِ گوگل (بخشِ اول، مرحله‌ی ۴) نشانیِ Pages را هم به
**Authorized JavaScript origins** اضافه کنید.

## عیب‌یابی

| نشانه | دلیل و راه‌حل |
|-------|----------------|
| دکمه‌ی گوگل اصلاً دیده نمی‌شود | `GOOGLE_CLIENT_ID` در `.env` خالی است، یا سرور ری‌استارت نشده، یا در تنظیماتِ گوگل نشانیِ سایت وارد نشده است. |
| `ورود با گوگل تأیید نشد` | نشانیِ سایت در Google Console با نشانیِ فعلی یکی نیست (http/https و www حساس‌اند). |
| `ورود با این دامنه‌ی ایمیل مجاز نیست` | `GOOGLE_ALLOWED_DOMAINS` را بررسی کنید. |
| `حساب کاربری فعالی با این ایمیل تعریف نشده` | یا `GOOGLE_AUTO_SIGNUP=true` کنید، یا کاربر را با همان ایمیل تعریف کنید (بخشِ سوم). |
| `This app isn't verified` | طبیعی است تا زمانی که برنامه را در گوگل تأیید نکنید؛ روی **Advanced → Go to app** بزنید. برای شرکت‌ها بهتر است مراحلِ تأییدِ گوگل را طی کنید. |

---

## چند توصیه‌ی امنیتی

1. همیشه `GOOGLE_ALLOWED_DOMAINS` را تنظیم کنید تا هر کسی با هر ایمیلِ گوگلی وارد نشود.
2. `GOOGLE_DEFAULT_ROLE` را روی `viewer` بگذارید و بعد از ورودِ فرد، نقشِ واقعی را
   مدیر سیستم به او بدهد.
3. در محیطِ واقعی، برنامه را در گوگل **Publish** کنید تا صفحه‌ی هشدارِ «تأیید نشده»
   برای کاربرانتان نیاید.
