# راهنمای کامل اجرای «راهکار» روی ویندوز ۱۱ (حالت سرور)

این راهنما قدم‌به‌قدم توضیح می‌دهد چطور برنامه را روی ویندوز ۱۱ با Node.js (نسخه ۲۰.۱۹ تا ۲۴ — از جمله **نسخه ۲۳**) در **حالت سرور** بالا بیاورید؛ یعنی یک فرآیندِ واحد که هم رابطِ کاربری را می‌دهد و هم API را، روی یک پورت (پیش‌فرض `8080`)، بدون Vite و بدون `npm run dev`.

---

## ۰) تفاوتِ «حالت توسعه» و «حالت سرور»

| | `npm run dev` (توسعه) | `npm start` یا `راه‌اندازی-ویندوز.bat` (سرور) |
|---|---|---|
| تعداد فرآیند | ۲ تا: Vite روی ۵۱۷۳ + API روی ۴۰۰۰ | ۱ تا: همه‌چیز روی ۸۰۸۰ |
| فونت/CSS | از فایل‌های پروژه، با Hot Reload | از خروجیِ ساخته‌شده (`dist/`) |
| مناسبِ | برنامه‌نویسی | استفاده‌ی واقعی، شبکه‌ی داخلی، سرور |
| نکته‌ی مهم | اگر API بالا نیاید، لاگین خطا می‌دهد | مستقل و پایدار |

---

## ۱) پیش‌نیازها

1. **Node.js** نسخه‌ی `20.19+` یا `22.12+` یا `23.x` یا `24.x` — از <https://nodejs.org> نصب کنید.
   در PowerShell بررسی کنید:
   ```powershell
   node -v      # مثلاً v23.11.1
   npm -v       # مثلاً 10.9.x یا 11.x
   ```
2. **Git** (اختیاری؛ برای دریافت و به‌روزرسانی پروژه).

> اگر PowerShell اجرای اسکریپت را می‌بندد (`npm.ps1 cannot be loaded`)، یک بار این را بزنید:
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```
> یا به‌جای PowerShell از **Command Prompt (cmd)** استفاده کنید.

## ۲) دریافت پروژه و ورود به پوشه

```powershell
git clone https://github.com/h03einsedaqat/erpv2.git
cd erpv2
```

## ۳) نصب وابستگی‌ها

```powershell
npm install
```

- اگر پیام‌های `npm warn EBADENGINE` دیدید، فقط **هشدار** است و نصب ادامه پیدا می‌کند.
- اگر با **خطا** متوقف شد (`npm error code EBADENGINE`)، یعنی روی سیستم شما `engine-strict` فعال است. بررسی:
  ```powershell
  npm config get engine-strict     # اگر true بود:
  npm config set engine-strict false
  ```
- `npm ci` هم کار می‌کند ولی سخت‌گیرتر است؛ برای نصب اولیه `npm install` ساده‌تر است.

> **چرا قبلاً خطای «نسخه‌ی خاصی از Node لازم است» می‌گرفتید؟**
> نسخه‌ی قبلیِ `package.json` همه‌ی وابستگی‌ها را روی `latest` گذاشته بود و `package-lock.json` به نسخه‌هایی قفل شده بود (مثل `jsdom@30`) که Node **۲۳** را پشتیبانی نمی‌کنند (فقط `22.22+` یا `24.15+`). حالا وابستگی‌ها روی نسخه‌های سازگار با Node ۲۰.۱۹ تا ۲۴ قفل شده‌اند.

## ۴) تنظیمات (اختیاری ولی توصیه‌شده)

```powershell
copy .env.example .env
notepad .env
```

حداقل این‌ها را بررسی کنید:

```env
PORT=8080
NODE_ENV=production
# اختیاری: اگر خالی بماند، برنامه خودش یک کلید پایدار در پوشه‌ی .data می‌سازد
JWT_SECRET=
```

برای ساخت یک کلیدِ تصادفی (اگر خواستید خودتان بگذارید):
```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

> **نکته:** در نسخه‌ی قبلی اگر `NODE_ENV=production` بود و `JWT_SECRET` نداشتید، سرور با خطا بالا نمی‌آمد. این مشکل رفع شده؛ سرور فایل `.env` را خودش می‌خواند و در نبودِ کلید، یک کلیدِ پایدار می‌سازد.

## ۵) اجرای حالت سرور — سه روش

### روش الف) ساده‌ترین: دوبار کلیک

روی فایل زیر دوبار کلیک کنید:

```
scripts\windows\راه‌اندازی-ویندوز.bat
```

این فایل خودش: وابستگی‌ها را نصب می‌کند (اگر نباشند) → خروجی را می‌سازد (اگر نباشد) → سرور را روی پورت ۸۰۸۰ بالا می‌آورد → مرورگر را باز می‌کند.

### روش ب) با npm (ساخت + اجرا در یک دستور)

```powershell
npm start
```

هر بار ابتدا `npm run build` اجرا می‌شود و سپس سرور بالا می‌آید. اگر `dist` را قبلاً ساخته‌اید و می‌خواهید سریع‌تر بالا بیاید:

```powershell
$env:SKIP_BUILD="1"; npm start
```

### روش ج) دستی (کنترل کامل)

```powershell
npm run build                       # ساخت خروجی در پوشه‌ی dist
$env:PORT="8080"
$env:NODE_ENV="production"
node --import tsx server/index.ts   # اجرای سرور
```

در cmd:
```bat
npm run build
set PORT=8080
set NODE_ENV=production
node --import tsx server/index.ts
```

## ۷) دسترسی از سایر سیستم‌های شبکه

سرور روی `0.0.0.0` گوش می‌دهد؛ یعنی از هر سیستم دیگری در شبکه با `http://IP-سیستم-شما:8080` قابل دسترس است. فقط باید فایروال ویندوز اجازه بدهد (PowerShell **با دسترسی Administrator**):

```powershell
New-NetFirewallRule -DisplayName "Rahkar ERP 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

IP سیستم خود را با `ipconfig` ببینید (مثلاً `192.168.1.20`).

## ۸) اجرای دائمی (سرویس ویندوز)

### گزینه‌ی ۱: NSSM (توصیه‌شده)

1. [NSSM](https://nssm.cc/download) را دانلود و `nssm.exe` را در یک مسیر (مثلاً `C:\nssm\`) بگذارید.
2. مسیر node را پیدا کنید: `where node` → مثلاً `C:\Program Files\nodejs\node.exe`
3. **cmd با دسترسی Administrator**:
   ```bat
   C:\nssm\nssm.exe install RahkarERP "C:\Program Files\nodejs\node.exe" "--import tsx server/index.ts"
   C:\nssm\nssm.exe set RahkarERP AppDirectory "C:\path\to\erpv2"
   C:\nssm\nssm.exe set RahkarERP AppEnvironmentExtra PORT=8080 NODE_ENV=production
   C:\nssm\nssm.exe set RahkarERP AppStdout "C:\path\to\erpv2\.data\service.log"
   C:\nssm\nssm.exe set RahkarERP AppStderr "C:\path\to\erpv2\.data\service-error.log"
   C:\nssm\nssm.exe start RahkarERP
   ```
   (قبلش یک بار `npm run build` را دستی اجرا کرده باشید.)
4. مدیریت: `nssm stop RahkarERP` / `nssm restart RahkarERP` / `nssm remove RahkarERP confirm`

### گزینه‌ی ۲: PM2

```powershell
npm install -g pm2
npm run build
pm2 start "node --import tsx server/index.ts" --name rahkar --cwd "C:\path\to\erpv2"
pm2 save
```
(برای اجرا هنگام بوت ویندوز از `pm2-windows-startup` یا Task Scheduler استفاده کنید.)

### گزینه‌ی ۳: Task Scheduler

یک Task با Trigger «At startup» بسازید که این را اجرا کند:
```
"C:\path\to\erpv2\scripts\windows\راه‌اندازی-ویندوز.bat"
```
با گزینه‌ی «Run whether user is logged on or not».

## ۹) پشتیبان‌گیری

- همه‌ی داده‌ها در پوشه‌ی `.data\` کنارِ پروژه هستند (`store.json` + کلید امضا + پشتیبان‌های خودکار).
- یک کپیِ زمان‌بندی‌شده از این پوشه کافی است. یا از داخل برنامه: **سازمان ← پشتیبان‌گیری و بازگردانی**.
- پشتیبان‌گیری خودکار با `BACKUP_INTERVAL_HOURS` در `.env` (پیش‌فرض هر ۱۲ ساعت، ۱۴ نسخه).

## ۱۰) رفع اشکال‌های رایج

| مشکل | علت | راه حل |
|---|---|---|
| فونت فارسی نمایش داده نمی‌شود / حروف مربعی‌اند | فایل‌های فونت (`.woff2`) در مخزن نبودند | رفع شد؛ ۱۰ فایل فونت وزیرمتن به `src/assets/fonts` اضافه شده. `npm run build` را دوباره بزنید و کش مرورگر را پاک کنید (`Ctrl+Shift+R`). |
| `npm ci` می‌گوید نسخه‌ی خاصی از Node لازم است | `package-lock` به نسخه‌های ناسازگار با Node 23 قفل بود | رفع شد؛ `npm install` بزنید. اگر باز خطا داد: `npm config set engine-strict false` |
| `Cannot find module './bootstrap-secret.js'` | فایل `server/bootstrap-secret.ts` در مخزن نبود | رفع شد (فایل اضافه شده). |
| در `npm run dev` لاگین می‌گوید «نام کاربری یا رمز عبور صحیح نیست» با رمز درست | سرور API (پورت ۴۰۰۰) به‌خاطر خطای بالا اصلاً بالا نیامده بود؛ Vite پاسخ ۵۰۰ می‌داد و رابط هر خطایی را «رمز اشتباه» نشان می‌داد | هر دو رفع شد. حالا پیام واقعی («سرور در دسترس نیست») نمایش داده می‌شود. |
| «برای اجرای عملیاتی باید JWT_SECRET تنظیم شود» | `NODE_ENV=production` بدون کلید | رفع شد؛ سرور خودش کلید پایدار می‌سازد. |
| `npm start` روی ویندوز `spawn npm ENOENT` می‌دهد | روی ویندوز npm یک فایل `.cmd` است | رفع شد؛ اسکریپت با `shell: true` روی ویندوز اجرا می‌کند. |
| پورت ۸۰۸۰ اشغال است (`EADDRINUSE`) | برنامه‌ی دیگری روی آن است | در `.env` مقدار `PORT` را عوض کنید، یا `netstat -ano \| findstr :8080` و پروسه را ببندید. |
| بعد از ری‌استارت همه کاربران باید دوباره لاگین کنند | کلید امضا هر بار عوض می‌شد | رفع شد؛ کلید در `.data\.jwt-secret` و `store.json` ذخیره می‌شود. پوشه‌ی `.data` را پاک نکنید. |
| تلاش‌های ورود زیاد بود (۴۲۹) | ۸ تلاش ناموفق پشت سر هم | چند دقیقه صبر کنید یا سرور را ری‌استارت کنید. |
